# AI VOC Analyzer

VOC 입력 → AI 분류 기준표 초안 → 검토·확정 → 고객 의견 자동 분류 → 기준 수정 → 변경된 기준으로 다시 분류 → 시각화를 연결한 로컬 Streamlit 앱입니다.

화면과 차트의 글꼴은 **프리텐다드**입니다. [공식 배포본 v1.3.9](https://github.com/orioncactus/pretendard/tree/v1.3.9/packages/pretendard)의 가변 글꼴을 `static/fonts/`에 포함해 외부 폰트 서버 없이 제공합니다. 사용 조건은 함께 포함한 `static/fonts/OFL.txt`에서 확인할 수 있습니다. 실행 중에 글꼴 설정을 변경했다면 앱을 다시 실행하고 브라우저를 새로고침합니다.

## 실행과 첫 분석

Python 3.14 환경에서 확인했습니다. 프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

[앱 열기](http://127.0.0.1:8501)

1. **1. 입력**에서 연습용 샘플·붙여넣기·CSV·XLSX 중 하나를 선택합니다.
2. 본문 열과 선택 사항인 분석 배경을 확인한 뒤 **입력 데이터 확인 → 입력 저장 → 분류 기준표로**를 누릅니다.
3. **AI 분류 기준표 초안 만들기**를 누릅니다. 표에서 대분류·세부분류·정의를 고치거나 행을 추가·삭제할 수 있습니다.
4. **분류 기준표 확정 → 고객 의견 자동 분류**를 누릅니다.
5. **3. 분류 결과 → 시각화·묶어보기**에서 여러 분류를 묶어 차트를 보고 원문·근거를 확인합니다. 현재 범위의 집계·원문·의견 CSV 또는 전체 실행 JSON을 받을 수 있습니다.

초안 표의 **내용 수정은 셀 더블클릭 → 입력 → Enter** 순서입니다. **행 삭제는 행 맨 왼쪽의 체크박스 선택 → 표 오른쪽 위 휴지통** 순서입니다. 도구 버튼은 표에 마우스를 올리면 나타납니다. 코드 ID는 자동으로 유지하므로 편집 표에서 숨겼습니다. 변경은 **분류 기준표 확정**을 눌러야 저장됩니다.

배운 **작업 의존성과 순차 진행**을 적용해, 저장된 원문이 분류 기준표의 근거가 되고 확정한 분류 기준표가 분류의 기준이 되게 했습니다. 화면에서 같은 VOC ID의 원문·분류 기준·여러 의견을 따라가며 이 연결을 확인할 수 있습니다.

## 저장된 입력 자료 관리

왼쪽 **저장된 입력 자료**에서 대상을 고른 뒤 바로 아래 **입력 자료 관리**를 펼칩니다.

- 저장 시각·입력 방법·응답 수·분류 기준표 수·분석 횟수를 확인합니다.
- **자료 이름**을 바꾸고 **이름 저장**을 누르면 목록과 분석 화면에 반영됩니다.
- **자료 삭제**를 누르면 선택한 이름과 함께 삭제할 범위를 표시합니다. **삭제 확인**을 눌러야 삭제되며 **취소**로 돌아갈 수 있습니다.
- 삭제하면 해당 입력의 원문·분류 기준표·모든 분석 결과·수정 이력·저장 묶음도 함께 삭제됩니다. 삭제 후 복구할 수 없습니다. 분류가 진행 중인 자료는 완료 후 삭제할 수 있습니다.
- 삭제 후에는 남은 자료로 전환합니다. 마지막 자료를 삭제하면 입력 화면으로 돌아갑니다.

배운 **상태·산출물 관리**를 적용해 입력 자료와 연결된 분석 정보를 함께 정리합니다. 삭제 전에 범위를 확인할 수 있고, 삭제 후 목록에서 대상이 사라져도 다른 자료의 분석 결과는 유지되는 것이 직접 확인할 결과입니다. 자료 관리에는 AI를 호출하지 않습니다.

## 결과에서 분류 묶어보기

**3. 분류 결과 → 시각화·묶어보기**에서 조작합니다.

1. **세부분류 직접 선택**에서 `오배송`, `배송 속도`처럼 함께 볼 항목을 여러 개 선택합니다. **대분류로 묶기**에서 `배송`을 선택하면 그 아래의 세부분류를 모두 포함합니다.
2. 선택 즉시 차트·고유 VOC 수·전체 응답 대비 비율·의견 수와 해당 원문이 갱신됩니다. **선택 범위의 감성**으로 좁히거나 **선택 초기화 · 전체 보기**로 돌아갈 수 있습니다.
3. **묶음의 원문 · 중복 제거**에서 응답을 한 건씩 보고, **선택한 의견과 근거**에서 세부 내용을 확인합니다. 각 탭에서 현재 선택 범위만 CSV로 받습니다.
4. 완료된 분석에서는 **이 조합을 저장해 다시 보기**에 이름을 입력해 저장합니다. 이후 **저장한 묶음 불러오기**에서 같은 실행의 분류·감성 조합을 다시 적용합니다.

분류 간 겹치는 원문은 VOC ID 기준으로 한 번만 셉니다. 같은 본문이어도 서로 다른 입력 행이면 별개 VOC로 유지합니다. **전체 응답 대비** 지표의 분모는 무응답을 포함한 해당 실행의 전체 원본 응답 수입니다. 감성은 선택한 분류의 의견에만 적용합니다. 진행·실패·검토 상태의 실행에는 잠정 집계임을 표시하고 완료 차트는 제공하지 않습니다.

묶어보기는 기존 코드를 모아 조회하는 기능이므로 AI 재호출 없이 동작합니다. 코드 의미를 하나로 바꾸는 통합·변경된 기준으로 다시 분류하는 작업과는 별개입니다. 배운 **사용 장면과 완료 조건의 구체화**를 적용해, 데이터를 본 뒤 선택을 바꾸면 건수·원문·내보내기가 같은 범위로 함께 바뀌게 했습니다.

## 시각화와 원문 탐색

- **대분류별 고유 VOC**, **세부분류 TOP N**, **감성이 포함된 고유 VOC**를 막대 차트로 제공합니다. 건수·비율 표시를 전환할 수 있습니다.
- 차트 막대를 누르면 현재 묶음 안에서 해당 분류 또는 감성으로 좁혀집니다. 아래 원문·의견·CSV도 같은 범위로 바뀝니다. **← 차트 선택 이전으로**는 직전 범위를, **선택 초기화 · 전체 보기**는 전체를 복원합니다. 분류·감성을 직접 바꾸면 이전 차트 선택 이력은 초기화됩니다.
- TOP N은 표시할 막대 수만 바꿉니다. 전체 집계표와 원문·다운로드에서 나머지 분류를 제외하지 않습니다. 대분류가 20개를 넘으면 상위 20개를 차트에, 전체를 집계표에 제공합니다.
- 전체 보기에서 **차트 비율의 분모**는 무응답 포함 전체 원본 응답입니다. 분류·감성 조건을 적용하면 현재 범위의 고유 VOC 수가 분모가 됩니다. 세부분류의 대분류 내 비율도 마우스 설명과 집계표에서 확인할 수 있습니다.
- 한 VOC가 여러 분류·감성에 포함되므로 비율 합계가 100%를 넘을 수 있습니다. 이를 강제로 정규화하지 않습니다. 내용 없는 응답에는 감성을 부여하지 않습니다.
- **차트 수치·분모 확인 및 내려받기**에서 전체 집계표와 CSV를 제공합니다. CSV에는 선택 범위·실행 ID·분류 기준표 버전·결과 개정 번호를 기록합니다. 차트의 카메라 버튼으로 PNG를 받을 수도 있습니다.

배운 **요구사항과 완료 조건의 구체화**를 적용해 ‘묶어보기 지원’을 단순 선택 상자가 아닌 **차트·수치·원문·내보내기의 동일 범위 유지**로 검증했습니다. 예를 들어 배송 속도와 오배송을 선택하면 다른 분류의 감성이 섞이지 않으며, 개별 결과를 저장한 뒤 차트에도 현재 수정본이 반영됩니다. 시각화 조회와 조작에는 AI를 호출하지 않습니다.

## 개별 결과 수정과 변경된 기준으로 다시 분류

**3. 분류 결과 → 개별 수정·승계 검토**에서 VOC 한 건을 고릅니다. 원문을 보면서 코드·감성·원문 근거·대상을 수정하거나 의견 행을 추가·삭제합니다. 수정 이유를 적고 **수정 저장**을 누르면 현재 결과와 묶음 집계에 반영됩니다. **편집 취소**는 저장 전 변경을 버립니다. 응답 상태를 ‘내용 없음·무응답’으로 바꾸려면 판단 이유가 필요하며, 반대로 의미 있는 의견으로 정정할 수도 있습니다.

**2. 분류 기준표**의 확정본 아래 **이 분류 기준표 수정·통합·분리**에서 새 버전을 만듭니다. 이름·대분류·기준·행을 편집하거나, 같은 대분류의 동일 의미 코드를 통합하거나, 한 코드를 두 개 이상으로 분리합니다. 통합은 대상을 선택하고 이름을 입력한 뒤 저장하면 되며 별도 확인 체크박스는 없습니다. 서로 다른 의미를 합쳐 조회할 때는 묶어보기를 사용합니다.

**통합·분리의 분류 기준은 선택 입력**입니다. 이름만 적고 저장하면 AI가 기존 분류 기준표·분석 배경·원문 표본을 참고해 빈 기준만 채워 새 버전으로 저장합니다. 직접 쓴 기준과 대분류·이름은 그대로 유지합니다. 생성에 실패하면 입력 내용을 유지하고 기존 버전을 보존하므로 재시도할 수 있습니다. AI 자동 생성에는 Gemini 설정이 필요하며, 기준을 모두 직접 입력하면 AI 호출 없이 저장합니다.

새 버전 저장 후 **수정값을 가져올 이전 분석**을 고르고 **변경된 기준으로 다시 분류**를 실행합니다. 이전 실행과 그 시작 시점의 수정 개정 번호를 고정해 가져오며, 다른 분기 실행이나 이후 수정은 섞지 않습니다. 전체 원문을 AI가 재평가한 뒤 사용자가 바꾼 항목만 승계합니다.

| 변경 상황 | 처리 |
| --- | --- |
| 관련 코드 유지·이름 변경·무관한 코드 변경 | 사용자 변경을 자동 반영하고 수정하지 않은 의견은 새 AI 제안 사용 |
| 같은 의미 코드 통합 | 명시적으로 저장한 이전 코드→새 코드 대응 사용 |
| 분리·삭제·정의 변경·근거 대응 불명확·사용한 배경 근거 삭제 | 해당 VOC를 승계 검토로 남기고 AI 후보를 완료 집계에서 제외 |

검토가 남으면 결과 화면의 **개별 수정·승계 검토**에서 이전 수정과 새 AI 후보를 비교하고 **검토 완료·수정 저장**을 누릅니다. 모든 미해결 건이 해소돼야 완료가 됩니다. 처음 결과 화면을 열 때는 이전 완료 실행이 기본이며 저장된 실행 선택으로 검토 중인 새 실행도 볼 수 있습니다.

배운 **상태·산출물 관리와 완료 조건**을 적용해 AI 최초 결과, 현재 수정본, 원래 수정 출처와 버전 이력을 구분했습니다. 직접 확인할 결과는 수정 후 같은 원문의 AI 최초 값이 보존되고, 표·묶음·다운로드에는 현재 값이 일관되게 나타나는 것입니다. 기준을 직접 입력한 분류 기준표 수정과 개별 결과 수정은 AI를 호출하지 않습니다. 통합·분리에서 빈 기준을 생성하는 경우에는 AI를 호출하며, 전체 VOC의 재평가는 전체 분류 버튼으로 시작합니다.

## Gemini 설정

프로젝트 최상위 `.env`에 `GEMINI_API_KEY=본인의키`를 저장합니다. 처음에는 `.env.example`을 복사해서 사용합니다. 화면에는 키를 표시하지 않으며 다른 프로젝트·전역 환경 변수의 키를 가져오지 않습니다.

- **설정 확인 / 연결 확인**은 모델 목록 조회만 수행합니다.
- AI 생성·분류 버튼을 눌러야 선택한 VOC 본문과 분석 배경이 Gemini로 전송됩니다. 별점·상품명·사람의 기존 코드 등 다른 열은 로컬에 보존하고 AI 입력에서 제외합니다.
- 현재 기본 모델은 `gemini-3.5-flash`이며 왼쪽 설정에서 바꿀 수 있습니다. 재시도에는 해당 실행에 저장된 모델을 사용합니다.
- 키 없이 입력·저장·기존 결과 조회를 사용할 수 있습니다. Gemini 사용에는 해당 계정의 API 한도·요금이 적용됩니다.

공식 SDK와 [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)을 사용하며, 구조가 맞는 응답도 코드 ID·원문 인용·배경 인용을 추가 검증합니다. 이는 의미상 분류 정확도의 보장은 아닙니다.

## 처리 규칙

- 파일 최대 10MB, 응답 최대 500행, 본문당 최대 5,000자, 공통 배경 최대 10,000자입니다. 초과하면 알리고 임의로 원문을 자르지 않습니다.
- 붙여넣기는 빈 줄을 제외한 한 줄을 한 건으로 읽습니다. CSV 형식상의 빈 줄도 제외합니다. CSV의 빈 셀·따옴표로 표현된 빈 응답, XLSX에서 ID 등 행 정보가 있는 빈 응답은 무응답으로 보존합니다. 중복 본문은 각각 다른 VOC입니다.
- 초안은 최대 100건·합계 60,000자 표본으로 생성합니다. 실제 표본 ID를 저장합니다. 전체 분류는 최대 10건·합계 20,000자씩 진행합니다.
- 한 VOC의 모든 의견과 감성을 각각 보존합니다. 긍정·부정이 함께 있으면 원문 전체 감성은 혼합입니다. 내용 없는 응답에는 감성을 부여하지 않습니다. 특정 역할이 없는 직원·담당자는 역할 미상으로 표시합니다.
- 기존 코드에 없는 의미는 근거와 함께 자동 보완하고 **전체 VOC를 새 분류 기준표로 다시 분류**합니다. 한 실행 요청에서 기본 최대 2회 보완하며 미해결 건을 완료로 표시하지 않습니다. 검토 후 보완을 최대 2회씩 더 실행할 수 있습니다.
- 의미 중복과 사용자 편집 의도는 AI에 비교를 요청하고, 동일 이름·정의 및 삭제·변경한 기존 정의의 재추가는 코드로도 차단합니다. 의미만 바꿔 쓴 중복이나 편집 충돌의 완전한 방지는 실제 자료로 추가 검증해야 합니다.
- 배경을 바꾸면 새 분류 기준표를 생성합니다. 이전 분류 기준표·실행의 배경과 결과는 그대로 남습니다.

## 저장·오류 복구

입력, 메타데이터, 분류 기준표 버전, 표본 ID, 자동 추가 근거, 실행별 배경·모델·프롬프트 버전과 AI 결과·수정 이력·승계 기준·묶음을 `data/voc_analyzer.db`에 저장합니다. 기존 DB에는 필요한 표·열만 추가하며 이전 자료를 유지합니다. 앱을 재시작하면 왼쪽 **저장된 입력 자료**와 결과 화면의 **저장된 분석 실행**에서 다시 열 수 있습니다. 원문이 포함된 로컬 DB와 `.local/` 검증 기록은 Git에서 제외합니다.

요청 한도·연결·응답 형식 오류는 제한적으로 재시도합니다. 근거·ID 검증에 실패한 VOC는 전체 의견 목록을 성공 결과에서 제외합니다. **실패·미처리 이어서 실행**은 성공 건을 보존하고 필요한 건만 재처리합니다. 자동 보완 시에는 새 회차에 전체 결과를 저장하고 이전 회차를 남깁니다. 진행 중 중단된 실행은 잠금이 만료되는 최대 6분 후 재개할 수 있습니다. 백그라운드 작업 서버는 아닙니다.

## 코드를 읽는 순서

- `src/ingestion.py`: 원문·빈 응답·행 식별자 준비
- `src/models.py`: 코드·의견·근거의 구조와 검증
- `src/storage.py`: SQLite에 버전과 실행 저장
- `src/ai.py`: Gemini 요청·프롬프트·제한 재시도
- `src/workflow.py`: 분류 기준표 확정, 분류, 자동 보완과 재개
- `src/results.py`: 원본 응답과 의견별 표·안전한 CSV 사본
- `src/grouping.py`: 선택한 분류의 고유 VOC 집계와 원문 연결
- `src/grouping_ui.py`: 묶음 선택·감성·저장/불러오기·범위별 다운로드
- `src/chart_data.py`: 고유 VOC 기준 차트 집계·분모·선택 범위·집계 CSV
- `src/charts_ui.py`: Plotly 막대 차트·선택 이벤트·집계표
- `src/codebook_changes.py`: 분류 기준표 변경·통합·분리와 명시적 버전 대응
- `src/corrections.py`: 원문 구간·변경 전후 기록, 수정 저장·승계·검토
- `src/codebook_ui.py`, `src/corrections_ui.py`: 새 버전 편집과 개별 수정·검토 화면
- `app.py`: 세 단계 화면과 사용자 동작 연결
