# AI VOC Analyzer

고객 의견(VOC)을 AI로 분류하고, 주제별 빈도와 감성을 확인하는 분석 도구입니다. AI가 만든 분류 기준을 사람이 검토·수정하고, 결과에서 원문까지 확인할 수 있습니다.

**[서비스 바로가기](https://voc-analyzer8220.streamlit.app/)** · **[발표자료 PDF 보기](outputs/presentation/VOC_Analyzer_발표자료_5장_텍스트.pdf)** · [사용 매뉴얼](static/manual/VOC_Analyzer_사용_매뉴얼.pdf)

> 공개 데모에는 **상품평 VOC 50건**이 준비되어 있습니다. 접속자는 같은 자료를 함께 조회·수정합니다. 비공개 고객 자료는 업로드하지 마세요. 배포 환경의 추가 수정분은 영구 보관을 보장하지 않으므로 필요한 결과는 Excel로 내려받으세요.

## 어떤 일을 할 수 있나요?

| 기능 | 할 수 있는 일 |
| --- | --- |
| VOC 입력 | CSV·Excel 업로드 또는 직접 붙여넣기 |
| 분류 기준 만들기 | AI 초안을 검토하고 대분류·세부분류·정의 수정 |
| 자동 분류 | 한 응답의 여러 주제와 감성을 구분하고 원문 근거 확인 |
| 결과 탐색 | 감성·분류별 그래프에서 관련 원문 조회 |
| 결과 보정 | 분류·감성 직접 수정, 분류 합쳐 보기, 변경 이력 확인 |
| Excel 내보내기 | VOC별 분류 결과와 분류별 통계 다운로드 |

Streamlit 화면, Gemini 분류, SQLite 저장, Plotly 시각화를 사용합니다.

## 사용 순서

이미 분석된 데모를 보려면 **분류 결과 → 상품평 VOC**를 선택하세요. 새 자료는 다음 순서로 분석합니다.

1. **데이터 입력** — 파일을 올리거나 고객 의견을 붙여넣고, 본문 열과 분석 배경을 확인해 저장합니다.
2. **분류 기준표** — **AI로 분류 기준표 만들기**를 누릅니다. 대분류·세부분류·정의를 검토한 뒤 **분류 기준표 저장**을 누릅니다.
3. **분류 실행** — **이 기준표로 VOC 분류하기**를 누릅니다. 확인이 필요한 응답이 있으면 결과 화면에서 검토합니다.
4. **결과 확인** — 감성을 선택해 범위를 좁히고, 대분류에서 세부분류로 이동합니다. 세부분류를 누르면 관련 원문이 열립니다.
5. **수정·다운로드** — 원문 표의 분류·감성 셀에서 수정하고, **다운로드** 메뉴로 Excel을 받습니다.

### 자주 쓰는 조작

| 하고 싶은 일 | 방법 |
| --- | --- |
| 원문 검색·필터 | 원문 표의 열 제목에서 검색하거나 값을 선택 |
| 분류·감성 수정 | 셀의 화살표 또는 더블클릭으로 편집 창을 열고 저장 |
| 분류 합쳐 보기 | 차트 행을 다른 행에 끌어 놓거나 행 메뉴에서 대상 선택 |
| 합친 분류 저장 | **지금 분류 저장** 메뉴에서 저장·불러오기·되돌리기 |
| 기준을 바꿔 다시 분석 | 기준표를 수정·저장한 뒤 다시 분류 실행 |
| 자료 이름 변경·삭제 | 상단 자료 선택 목록의 연필·× 사용 |

**자료의 ×를 누르면 확인 창 없이 원문·기준표·결과·수정 이력이 함께 삭제되며 복구할 수 없습니다.** 분류 진행 중인 자료는 삭제할 수 없습니다.

기준표를 바꿔 다시 분석할 때는 이어받을 수정이 있는 경우 **직접 수정한 분류 결과 유지**를 선택할 수 있습니다. 새 기준과의 대응이 불명확한 응답은 별도 검토 대상으로 남습니다. AI로 기준표를 새로 생성한 경우에는 이전 수정값을 자동 승계하지 않습니다.

## 통계는 어떻게 계산하나요?

**집계 단위는 고유한 VOC ID입니다.** 같은 응답이 한 분류를 여러 번 언급해도 그 분류에서는 1건으로 셉니다. 같은 본문이라도 입력 행이 다르면 별개 응답입니다.

> 분류 비율 = 해당 분류를 언급한 고유 VOC 수 ÷ 기준 응답 수 × 100

| 기준 | 분모 |
| --- | --- |
| 전체 기준 | 무응답을 포함한 전체 응답 수 |
| 유효 기준 | ‘없음·무응답·모름’으로 분류된 응답만 제외한 수. 중립은 포함 |

예를 들어 전체 100건 중 무응답이 20건이고 흡입력 언급이 30건이면, 전체 기준은 **30%**, 유효 기준은 **37.5%**입니다.

- **복수 분류:** 한 응답이 흡입력과 소음을 모두 언급하면 각각에 포함됩니다. 분류별 비율의 합은 100%를 넘을 수 있습니다.
- **대분류·합친 분류:** 하위 분류 건수를 단순히 더하지 않고, 겹치는 VOC ID를 한 번만 셉니다.
- **첫 화면의 감성 언급률:** 긍정·부정이 함께 있는 응답은 양쪽에 포함됩니다. 두 비율의 합이 100%를 넘을 수 있습니다.
- **상세·Excel의 감성 구성:** 긍정·부정·혼합·무응답/중립/미검토로 나눕니다. 해당 범위의 응답을 한 번씩 세므로 합은 100%입니다.
- **화면 감성 필터:** 선택한 감성을 포함한 응답을 기준으로 분류 그래프를 다시 계산합니다.

### 다운로드 범위

| 파일 | 내용 |
| --- | --- |
| VOC별 분류 | VOC ID·원문·대분류·세부분류·감성. 복수 분류는 여러 행으로 표시 |
| 분류 통계 | 대분류·세부분류별 건수·비율·감성 구성 |

다운로드 메뉴에서 **전체 기준·유효 기준**을 선택할 수 있습니다. 화면의 감성·분류 필터와 표시 개수 제한은 다운로드에 적용하지 않습니다. 합친 분류는 통계 Excel에 반영하고, VOC별 Excel에는 원래 분류를 유지합니다. 각 파일의 **집계 기준** 시트에서 분모와 계산 규칙을 확인할 수 있습니다.

## 로컬에서 실행하기

Python 3.14 환경에서 확인했습니다. 프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

AI 기능을 사용하려면 `.env.example`을 `.env`로 복사하고 본인의 키를 입력합니다. 기존 `.env`가 있다면 그대로 사용하세요.

```dotenv
GEMINI_API_KEY=본인의키
```

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

[로컬 앱 열기](http://127.0.0.1:8501)

키 없이도 입력·저장·기존 결과 조회는 가능합니다. 로컬에서는 프로젝트 루트의 `.env`를 읽으며, 전역 환경 변수의 키는 사용하지 않습니다. `.env`와 로컬 DB는 Git에서 제외합니다.

### AI에 전달되는 정보

AI 생성·분류 또는 빈 분류 기준 보완을 실행할 때 VOC 본문과 분석 배경이 Gemini로 전송됩니다. 별점·상품명·사람이 부여한 기존 코드 등 추가 열은 AI 입력에서 제외합니다. 조회·결과 수정·묶어보기에는 AI를 호출하지 않습니다.

기본 모델은 `gemini-3.5-flash-lite`이며, 재시도는 해당 실행에 저장된 모델을 사용합니다. API 사용에는 해당 계정의 한도·요금이 적용됩니다.

## 저장과 운영

입력·분류 기준표 버전·분류 결과·수정 이력·저장 묶음은 `data/voc_analyzer.db`에 저장합니다. 로컬에서는 앱을 재시작한 뒤 저장된 자료를 다시 열 수 있습니다.

- **실패한 분류:** **실패·미처리 이어서 실행**으로 성공 건을 보존하고 필요한 응답만 재처리합니다.
- **중단된 분류:** 실행 잠금이 만료되는 최대 6분 후 재개할 수 있습니다. 별도의 백그라운드 작업 서버는 없습니다.
- **공개 데모:** `data/public_demo.json`의 상품평 VOC 50건을 `.env`가 없는 환경에 최초 한 번 추가합니다. 이후 수정·삭제는 덮어쓰지 않으며, 서버 저장소가 초기화되면 기본 데모부터 다시 시작합니다.

## 처리 범위와 한계

| 항목 | 제한 |
| --- | --- |
| 파일 | CSV·XLSX, 최대 10MB |
| 응답 | 최대 500행, 본문당 5,000자 |
| 공통 분석 배경 | 최대 10,000자 |
| 기준표 초안 표본 | 최대 100건·합계 60,000자 |
| 분류 배치 | 최대 10건·합계 20,000자 |

붙여넣기의 빈 줄은 제외합니다. 파일에서 행 정보가 있는 빈 응답은 무응답으로 보존하며, 길이 제한을 넘은 원문은 임의로 자르지 않습니다.

AI 초안은 자동 검사와 별도 AI 품질 검토를 거칩니다. 코드 ID·원문 근거 등을 검증하지만 **의미상 분류 정확도를 보장하지는 않습니다.** 기준표와 개별 결과를 사람이 검토할 수 있도록 원문과 수정 이력을 제공합니다.

기존 기준에 담기지 않은 의미는 기준을 보완해 전체 VOC를 다시 분류합니다. 한 실행 요청에서 기본 최대 2회 보완하며, 미해결 응답을 완료로 처리하지 않습니다. ‘기타’ 비중 10~15%는 검토 신호이며 강제 상한이 아닙니다.

**남은 과제:** 실제 사람이 분류한 자료와의 품질 비교, 결과 개정에 연결한 AI 인사이트 제공.

## 개발·검증

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

자동 검사는 실제 API를 호출하지 않고 임시 DB를 사용합니다. 입력·집계·수정 이력·재분류·오류 복구 등을 검사합니다. 2026-10-08 기준 전체 336개 검사가 통과했습니다. 이는 기능 검증 결과이며 실제 업무 자료의 분류 정확도 평가는 아닙니다.

<summary>실제 API 점검과 코드북 품질 비교</summary>

아래 명령은 실제 API를 호출합니다. 가상 응답 30건의 연결·처리 점검 결과는 `.local/`에 저장합니다.

```powershell

```

기존 실행과 새 코드북의 품질 비교는 별도 `.local/` DB에서 수행합니다. API 실행에는 `--execute`가 필요하며 기존 DB와 수정 이력은 변경하지 않습니다.

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_codebook_quality.py --source-run <실행_ID> --execute
```

비교에는 코드 수·중복·정의·기타 비중·미해결 응답·AI 검토 등이 포함됩니다. 코드 수나 기타 비중 감소만으로 개선을 판정하지 않고 원문 대비 누락·경계·과세분화를 함께 검토해야 합니다.
